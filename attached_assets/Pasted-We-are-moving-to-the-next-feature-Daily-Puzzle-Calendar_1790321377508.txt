# FEATURE 1 — DAILY PUZZLE

Add a small **calendar icon (📅)** near the top-right of the main game UI, directly below/around the existing coin display.

The player taps the calendar icon to open a dedicated Daily Puzzle calendar screen.

## CALENDAR SCREEN

Show:

* Current month
* Dates arranged in a normal calendar layout
* A clear indication of today's date
* Completed dates should display a **crown (👑)** or crown-style completion indicator
* Available dates should look playable
* Future dates should look locked/unavailable
* Dates older than the allowed window should look locked/unavailable

Keep the design consistent with the existing Word Hunt visual style. Do not make the calendar oversized or visually dominant.

## DAILY PUZZLE AVAILABILITY WINDOW

The player can play:

* today's Daily Puzzle
* plus the previous **5 calendar days**

Therefore there are always up to **6 playable dates**.

Example:

If today is **September 25**:

PLAYABLE:

* September 20
* September 21
* September 22
* September 23
* September 24
* September 25

NOT PLAYABLE:

* September 19 and earlier
* September 26 and later

This must be a rolling window based on the current local calendar date.

Do NOT interpret "past 5 days" as only five total dates. The example above explicitly means **today + previous 5 days = 6 dates**.

When the date changes to September 26, the playable window should automatically become:

* September 21
* September 22
* September 23
* September 24
* September 25
* September 26

September 20 should then become unavailable.

## DATE HANDLING

Use the player's local calendar date consistently.

Do not depend on a server clock for this feature.

Avoid UTC date conversion bugs where late-night users could accidentally see the wrong Daily Puzzle date.

Create a stable date key such as:

`YYYY-MM-DD`

and use that key consistently for:

* puzzle seed
* completion persistence
* determining the playable window

## DAILY PUZZLE DETERMINISM

Each date must have its own deterministic Daily Puzzle.

For example:

`2026-09-25` always generates the same Daily Puzzle.

If the player:

* closes the app
* reopens it
* returns later
* plays from the calendar again

the puzzle for that date must remain the same.

Use the existing puzzle generation engine with a deterministic seed derived from the date.

Do NOT use Date.now() as the Daily Puzzle seed.

Different dates should produce different puzzles.

## DAILY PUZZLE COMPLETION

When the player completes a Daily Puzzle:

* award exactly **+20 coins**
* mark that date as completed
* show the completion state in the calendar using a crown (👑)
* prevent the player from receiving another +20 for the same date

Completion must persist across:

* app restart
* browser refresh
* Android app close/reopen
* navigation away and back

The reward must be exactly-once.

Double tapping, replaying, or reopening the completed Daily Puzzle must never award another +20.

Use the existing persistence architecture rather than relying on in-memory state.

Store completed daily dates separately from normal `completedLevels`.

For example, use a dedicated persisted collection of date keys.

Do NOT treat a Daily Puzzle as completing a normal category level.

## DAILY PUZZLE REPLAY

If a date is within the current 6-day window and has already been completed:

* the player may open/view that Daily Puzzle if appropriate
* but it must not award another 20 coins
* the calendar must continue showing that date as completed

If the cleaner UX is to prevent replay entirely after completion, that is acceptable, but do not allow another reward under any circumstance.

## DAILY PUZZLE REWARD FLOW

Daily Puzzle should have its own clear completion result:

`Daily Puzzle Complete!`

`+20 Coins`

Then allow the player to return to the calendar/game.

Do not accidentally trigger:

* normal +50 coins
* category completion
* onboarding progression
* normal category unlock
* normal completion reward logic

The Daily Puzzle is its own mode.

IMPORTANT:
Do not invent a Mystery Dumpling reward for Daily Puzzle unless the existing architecture makes that unavoidable. The explicitly requested Daily Puzzle reward is **20 coins** and the Daily Puzzle must not interfere with the normal progression/reward system.

Main screen

→ Daily Puzzle

→ return to Calendar/results

The initial calendar should open to the current month.

Allow viewing other months if useful, but the availability rules must remain strict:

* only the current date and previous 5 dates are playable
* future dates cannot be played
* dates older than the rolling 6-day window cannot be played

If month navigation is implemented, make unavailable dates visibly locked rather than allowing them to launch a puzzle.

Do not over-engineer this feature.
