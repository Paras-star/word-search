==================================================
BANNER ADS
==========

Implement a Banner ad in a reserved, non-overlay location.

Preferred initial placement:

* Category selection/results area
* NOT the active puzzle grid
* NOT over letters
* NOT during dragging
* NOT during word selection
* NOT during Mystery Dumpling reveal
* NOT in the Collection Room
* NOT immediately on initial app launch

The banner must have its own layout space.

Never position it over interactive game content.

If the banner fails to load, the game must continue normally and the empty ad area should not create a broken-looking layout.

Keep the banner implementation isolated so we can move its placement later without touching gameplay.

==================================================
INTERSTITIAL ADS
================

Implement interstitial ads only at natural between-level transitions.

Preferred flow:

Complete puzzle
→ save progress
→ award coins
→ process Mystery Dumpling reward
→ finish reward/reveal flow
→ player proceeds toward the next level
→ optionally show interstitial

IMPORTANT:

* Never show an interstitial while the player is solving a puzzle.
* Never show it during letter selection.
* Never interrupt the Mystery Dumpling reveal.
* Never show it immediately on app launch.
* Never block progression if an ad isn't loaded.
* Never show an ad if loading failed.

Add sensible frequency control.

Do NOT show an interstitial after every single level.

Use a conservative initial frequency such as after every 3 completed puzzles, or another similarly reasonable threshold.

Make this threshold easy to modify later.

The app should continue normally if no ad is available.

==================================================
REWARDED ADS
============

Implement Rewarded Ads as an explicit optional action.

Reward:

WATCH REWARDED AD → RECEIVE COINS

Do NOT:

* reroll Mystery Dumplings
* modify rarity
* modify the dumpling catalog
* create duplicate collection logic
* bypass puzzle completion
* automatically show rewarded ads
* force the user to watch an ad

The player must explicitly choose to watch the ad.

Only grant the coin reward after the SDK confirms that the user earned the reward.

Do not grant the reward merely because the ad opened.

If the player closes the ad without earning the reward:

* grant nothing
* do not penalize the player
* allow normal gameplay

Make the rewarded coin amount configurable in one place.

Start with a reasonable value such as:

+50 coins

but keep this easy to change later.

The rewarded-ad UI should clearly communicate what the player receives before they choose to watch.

==================================================

========

During development/testing, use Google's official test ad IDs or the SDK's official test configuration.

Do NOT generate invalid/fake production IDs.

Do NOT risk invalid-ad-traffic problems by repeatedly testing against production ads.

Make it easy to switch between test and production IDs for the final release.

Do not hardcode a confusing mixture of test and production IDs.

==================================================
CONSENT / PRIVACY
=================

Implement Google UMP consent handling appropriate for AdMob.

Before requesting personalized advertising where required:

* request/update consent information
* respect the user's consent status
* only request ads according to the resulting consent state
* provide a way for the user to revisit privacy choices later

Do not invent your own fake consent dialog if the official UMP mechanism can handle this.

Keep consent handling isolated in a dedicated service/module.

The game must still function if the user:

* denies consent
* does not provide consent
* cannot load the consent information
* is in a region where the consent flow differs

Ads must never prevent gameplay.

Do not implement unnecessary tracking or analytics.
